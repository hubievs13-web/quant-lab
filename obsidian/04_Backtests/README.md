# 04_Backtests

One folder per backtest run, not one flat note. Naming:

```
obsidian/04_Backtests/BTxxxx_Hxxxx_YYYY-MM-DD/
  report.md         # Obsidian-side report (template below)
  overview.png      # secondary
  equity_curve.png  # secondary
  trades.csv        # primary
  orders.csv        # primary
  logs.txt          # primary
  statistics.txt    # primary (if available)
  statistics.json   # primary (if available)
  report.pdf        # secondary (if exported)
```

`report.md` is generated by `scripts/process_qc_backtest.py` from the
raw files placed in `results/raw/BTxxxx_Hxxxx_YYYY-MM-DD/`. The script
also upserts `results/experiments.csv`.

## Evidence policy

- PRIMARY evidence: machine-readable artifacts. trades.csv, orders.csv,
  logs.txt, statistics.* . The Devin chat needs at least the primary
  set to issue anything beyond INCONCLUSIVE.
- SECONDARY evidence: screenshots and report.pdf. Useful, but never
  sufficient alone.
- If only secondary evidence is present:
  - `evidence_confidence: LOW_CONFIDENCE` in the report front matter.
  - `verdict_draft: INCONCLUSIVE_DRAFT`.
  - The Devin chat should request the primary files before deciding.

## How to fill

1. Run the backtest in QuantConnect (project 30774195, Lean v17685).
2. Drop raw files into `results/raw/BTxxxx_Hxxxx_YYYY-MM-DD/`.
3. Run:
   ```
   python scripts/process_qc_backtest.py \
       --hypothesis Hxxxx --strategy Sxxxx \
       --raw-dir results/raw/BTxxxx_Hxxxx_YYYY-MM-DD \
       --symbols BTCUSDT,ETHUSDT --timeframe 1m \
       --is-window IS_START:IS_END --oos-window OOS_START:OOS_END
   ```
4. Inspect `obsidian/04_Backtests/BTxxxx_Hxxxx_YYYY-MM-DD/report.md`.
   The script fills metrics it can extract; everything else is UNKNOWN
   or MISSING. Do NOT hand-edit fields to fabricate values.
5. Send the report and the PRIMARY files (and screenshots if helpful)
   to the Devin chat. Devin returns a final verdict.
6. After the verdict arrives, run Codex auditor in post-verdict mode
   to update files and `experiments_log.md` and to upsert the verdict
   into `results/experiments.csv`.

## Verdict semantics

- `verdict_draft` (script / template): FAIL_DRAFT, INCONCLUSIVE_DRAFT,
  READY_FOR_DEVIN_REVIEW. Never a final value.
- `verdict` (Devin only): FAIL, INCONCLUSIVE, PRELIMINARY_PASS,
  FINAL_PASS.

The script and Codex must NEVER write into `verdict`. Only the user,
relaying the Devin chat's decision, sets that field.
